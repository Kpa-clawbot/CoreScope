# v3.15.0

77 commits since v3.14.0: 27 fix, 23 perf, 19 feat, 3 test, 2 ci, 2 docs (one of them
these notes), 1 chore. Nineteen feats, so minor.

The headline is node liveness (#2260): a repeater only counts as heard when the
evidence can only be that repeater. The rest is mostly memory and latency work on
the packet store, optional LoRa radio settings per node, and companion linking for
instances with user accounts.

## Read this before upgrading

These change what a running instance does without being asked.

- **Last Heard and node status count only certain evidence** (#2261, closes #2260).
  Before, a relay hop counted as "heard" for whichever node the resolver picked, so a
  1-byte hop shared by many repeaters kept a silent one "Active". Now only the node's
  own packets and flood relay hops whose prefix matches no other repeater, and no
  retired one, count. Adverts with an invalid signature no longer count.
  - `last_heard` in `/api/nodes` and the node detail can now differ from `last_seen`
    (it was a copy of it).
  - A new status `uncertain`: a repeater or room with nothing certain in the silent
    window whose shared prefix still shows up in paths. Grey badge, filter buttons on
    the nodes list and the map, dimmed on the map like stale.
  - Watched-node offline mails now fire for repeaters that were kept green by a
    namesake prefix.
  - Counts on one staging instance with 1,682 repeaters and rooms, on the day of the change:
    1,497 active, 117 uncertain, 68 stale. No before/after count of the same moment was
    taken. Right after a restart the uncertain count starts lower, because the cold
    load skips ambiguous relay hops (#1643); it grows with live traffic.
- **Node analytics use only certain data for Availability and Longest Silence**
  (#2262). The activity chart is stacked into certain and uncertain. A silence that is
  still running now counts. Rates for 30 d and All cover only the data in memory and
  the page says from when (#2211): on one staging node the 30 d availability went from
  19.3% to 83.3%, because days before the in-memory span counted as silent.
- **`users.db` migrates to schema v6 at startup when user accounts are on** (#2174).
  A v3.14.x binary refuses the file afterwards, so a rollback needs the backup from
  before the upgrade (`backups/` next to `users.db`).
- **The ingestor starts a background backfill at every start** (#2133). It rewrites
  `enc_*` channel hashes and empty scope names once a matching key is known, and runs
  again when the key set grows. It creates three tables in the analyzer database
  (`tx_rewrite_feed`, `key_backfill_state`, `key_backfill_done`). The PR gives no
  measured cost on a large database.
- **Planner statistics refresh at most once per 24 h** (#2158). A restart within 24 h
  of the last refresh runs no `ANALYZE`; a file `<db>.planner-stats-refreshed` is
  written next to the database. The first start after the upgrade still runs it. One
  `ANALYZE` took 7 min 50 s on a large database.
- **Answers can be older than before, in exchange for latency:**
  - `/api/nodes` answers identical queries from a shared cache for up to 15 s
    (#2165). A geo-filter, blacklist or hidden-prefix change clears it. Measured on one
    deployment: p95 165.4 to 114.4 ms, allocation 1,000 to 594 MB.
  - The neighbor graph is only rebuilt in the background, every
    `neighborGraph.cacheRecomputeIntervalSeconds` (default 300) (#2222). A rebuild took
    11.1 to 11.4 s on the request path before.
  - Server caches past their 30 s TTL serve the old value while one refresh runs
    (#2147), and `/api/perf` row counts are up to 60 s old (#2156).
- **Hop names and region placement change:**
  - `iataCoords` gains 104 BE, NL, LU, DE and FR codes, and region narrowing now
    applies only to the directly heard hop (#2188, closes #2098).
  - `/api/nodes?region=` places a node by its zero-hop home regions first, then by the
    fewest hops up to `regionFallback.maxHops` (default 3) (#2190, closes #1879). Every
    node row gains `region_placement`.
  - Transport-direct zero-hop adverts are now detected (#2234, closes #2225).
  - The packet detail and the map route view infer 1-byte hops as one whole path;
    hops can show as "unlisted" (#2245).
  - An observer's own transmissions (`direction='tx'`) no longer count as receptions
    in Heard By and the neighbor graph (#2220). Existing neighbor edges keep their
    counts.
- **Favorites and home status cards use the role's thresholds** (#2215): a repeater
  is degraded after 24 h and silent after 72 h there, as on its node page, instead of
  1 h and 24 h.
- **A geo-filter save on a single-file `config.json` mount now fails with 500**
  (#2137). It used to write a copy that the next start discarded. A symlinked
  `config.json` is now written through.
- **Hidden tabs stop polling `/api/stats`** (#2162); a visible tab refreshes it at most
  once per 15 s.

## Features

- **LoRa radio settings per node** (#2209, #2210, closes #1268). A LoRa row on the node
  detail (frequency, SF, BW, CR, preset) from the MeshCore map, and a badge plus
  `?lora=differs` filter for nodes whose settings differ from nodes within
  `rfParams.compareRadiusKm` (50 km). Off until `rfParams.nodesUrl` is set.
- **Observer TX airtime** (#2208, closes #661). A rolling 1 h TX airtime column on the
  observer list and a tile on RF Health, with a warning above `dutyCycleWarnPct`
  (10%).
- **Adaptive offline threshold for notifications** (#2262). Off by default:
  `userManagement.notifications.adaptiveOffline.enabled`. It learns each watched
  node's normal silence and mails about 30 minutes into an outage instead of after the
  fixed window.
- **External node alerts feed** (#2178, closes #2177):
  `userManagement.notifications.externalAlerts` turns an external JSON feed into
  `node.external` mails for watched nodes.
- **Companion linking** (#2174, #2175, #2176). With user accounts on, a companion app
  links to an account with a device token. `clientRxCoverage.requireLinkedCompanion`
  ingests coverage only from linked companions; the account page lists them, with a
  "My coverage" view.
- **Coverage gaps** (#2172). The Mobile RX coverage page shows where a companion drove
  and received nothing, for instances with `clientRfSamples`.
- **Repeaters known only by a reported name** (#2239). Opt in with
  `clientNodeNames.enabled`: names that companions report are stored, used in hop
  resolution, and shown with an estimated position.
- **Scope Audit transport view** (#2167, #2169, #2171). Every repeater seen forwarding
  a scope, next to the declared view, and an observer region filter for both.
- **Region filter**: `?region=` in the URL works on every page (#2256, closes #2255),
  and `regionQuickPicks` adds configured groups to the control (#2170).
- **`?theme=dark|light`** URL parameter for one page load (#2251, closes #2236).
- **Postal as mail provider** for user accounts (#2154):
  `userManagement.mail.provider: "postal"`.
- **Rolling hop index for the reach report** (#2214). Opt in with
  `retention.hopIndexDays`. One reach scan went from 816 ms to 293 ms in the benchmark;
  the index cost about 2 GB on a large database.
- **Docker: run the Go services as an unprivileged user** (#2125, #2235). Set
  `RUN_AS_UID` / `RUN_AS_GID`; unset, the services run as root as before.

## Fixes

- **Server locks**: no SQL while holding the packet-store lock (#2147); region and
  area sets are resolved before taking it (#2247, closes #2219); data races between
  ingest and HTTP readers (#2246, closes #2237).
- **Pages**: late responses no longer overwrite a newer page visit on node analytics,
  analytics and the account page (#2248, closes #2200, #2218, #2230); the packets node
  filter keeps its pick (#2244, closes #2243) and grouped mode re-fetches on an
  observer change (#2242, closes #2241); live packets respect the channel filter
  (#2192, closes #2191).
- **Analytics**: Packets / Hour is readable on long histories (#2194, closes #2193);
  Route Patterns applies `nodeBlacklist` and `hiddenNamePrefixes` (#2189, closes
  #2184).
- **Route view**: "N hops" counts only true hops (#2240, closes #2206), and
  payload-decoded sender and recipient rows get a badge (#2207).
- **Reach**: the reach page retries a busy (429) report (#2250).
- **Accounts**: a re-registration updates password and name in one statement (#2253,
  closes #2228).
- **Ingestor**: an interrupted background migration is recorded as cancelled and
  retried (#2161); the background chunk loader sets `observer_iata` (#2185).

## Performance

- **Request path** (#2146): the reach scan is driven by the observations time window
  (#2155, 14.11 s to 1.93 s on one query); `/paths` reads in batches (#2157, #2224,
  closes #2223); battery history uses the primary key (#2156); per-region scope counts
  use the `first_seen` index (#2166, closes #2146: 1 h window 3.08 s to 16 ms); the
  neighbor graph leaves the request path (#2222, closes #2221).
- **Packet store memory** (#2181 to #2183, #2186, #2187, #2195 to #2199, #2201, #2163,
  closes #2148). One deployment: startup to ready 31 s to 21 s (#2181), subpath index
  RSS 948 to 767 MB (#2182), heap 581 to 535 MB from shared observer strings (#2183).
- **Ingestor**: live ingestion runs between retention batches (#2153, closes #2151).
- **Opt-in `analytics.pauseWhenIdle`** skips recomputes nobody reads (#2164): 459.7 to
  53.4 MB allocation in the measurement.
