# v3.13.0

16 commits since v3.12.0: 10 fix, 4 test, 2 feat. Two feats, so minor not patch.

## Read this before upgrading

**The first start after this release backfills advert route evidence in the
background, and flood counts read low until it finishes.**

#2088 records, per advert, whether it was seen arriving by flood, by direct with
an empty path, or both. New adverts get this at ingest. For the adverts already
in your database, the ingestor runs a one-off background job
(`advert_route_evidence_v1`) that reads their stored observations. Until it
completes, the Analytics advert split and each node's flood-advert count only
know the adverts it has reached so far, so they undercount.

Measured on two instances of the same deployment, both on a 4-core ARM64 host:

| | observations | database | duration |
|---|---|---|---|
| live | 16.8M | 10.6 GB | 24m 1s |
| staging, sharing the host with live | 16.5M | 10.3 GB | 36m 23s |

The author measured 5m43s on 11M observations on other hardware, so expect a
wide spread.

Startup does not wait for it, and ingest carries on alongside it: on the live
instance the 15 minutes from 13:00, inside the backfill window, stored 2,803
observations against 2,605 to 3,194 in the quarter hours before the deploy.

It runs once per database. Its progress is kept in the database
(`advert_evidence_backfill` holds the cursors, `_async_migrations` the status),
so a restart resumes rather than repeats it. There is no setting to skip it.

What it cannot recover: an observation that was overwritten before this release
keeps only its last frame, so some old adverts stay unclassified. The Analytics
page says so under the chart.

## Features

- **Adverts are split by the route they arrived on** (#2088, closes #2041) -
  Analytics separates flood adverts from direct adverts with an empty path, and
  shows adverts seen both ways as mixed. Node flood-advert counts use the same
  evidence. An empty remaining path is labelled as exactly that: the firmware
  can forward a direct advert down to an empty path, so it does not prove the
  advert was sent zero-hop or from nearby. If writing the evidence fails, the
  error is logged and counted and the observation is still stored.
- **Node detail groups recent adverts the same way** (#2085, closes #2073) -
  both the side pane and the full page group by the server's classification.
  An advert without evidence goes to "other" rather than being guessed from the
  first stored frame, which could belong to a different route than later
  observations of the same advert.

## Paths and packets

- **Path hops are resolved with the observer that heard them** (#2099, closes
  #2097) - a 1-byte hop prefix matches several repeaters. Resolution now uses the
  receiving observer's position, and the packets list shows one warning at the
  start of a path saying how many of its hops have more than one candidate. The
  detail pane keeps a badge on each such hop, tied to its name.
- **The packets table is compact** (#2090) - short columns such as time, size
  and hop count are sized to their content instead of a share of the screen, a
  grouped row draws one expand arrow, and a **Full Names** toggle shows observer
  and hop names unabbreviated.
- **Packet links keep the selected observation** (#2093, closes #2091) -
  changing the type or observer filter no longer drops `?obs=` from the URL.

## Interface

- **Channel state survives a channel-list refresh** (#2096, closes #2095) -
  unread counts, last-message previews and the channels you added with a key
  are kept when the region filter or the show-encrypted toggle reloads the list.
  Before, every unread count reset and an open key-only channel was closed.
- **Live accepts node-filter input only once it can process it** (#2103, closes
  #2094) - typing while the initial node list loaded was silently lost.
- **Heard By drops a Region column that was always empty** (#2077, closes
  #2062) - the endpoint never sent that field.
- **Navigation and channel buttons are one size, 48px** (#2078, closes #2052).
- **The route sidebar no longer covers Path Inspector candidates** (#2082,
  closes #2060 and #2081).

## Upgrade notes

No manual migration step. #2088 adds the `advert_route_evidence` table, created
at boot, and the background backfill described at the top fills it for existing
adverts. It needs no action, only the awareness that flood counts are low until
it finishes.

Nothing is opt-in and no configuration key was added or changed.
