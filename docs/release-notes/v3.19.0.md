# v3.19.0

32 commits since v3.18.0: 14 fix, 8 feat, 5 test, 2 ci, 2 docs, 1 refactor. Eight feats,
so minor not patch.

This release changes three things a running instance does without being asked. The
analyzer database gets a one-time rebuild of its observers table. An old content-hash
migration finally runs. And signal figures per node now come only from receptions of the
node itself, so many SNR numbers change. New features are all opt-in. They include a
Coverage tab in the repeater planner, more map providers, plain SMTP for account mail,
and repeater claims from mobile apps.

## Read this before upgrading

### The ingestor rebuilds the `observers` table once

On its first start the ingestor rebuilds `observers` in the analyzer database with an
explicit `idx INTEGER PRIMARY KEY` (#2407, #2445). Every observation stays linked to the
same observer. The table has one row per observer, so this takes a moment, not minutes.
Indexes, triggers and views you added yourself on `observers` are recreated afterwards.

The rebuild refuses rather than lose data in two cases:

- `observers` has a column CoreScope did not create. The rebuild would drop it.
- A row has a NULL `id`: `SELECT rowid, * FROM observers WHERE id IS NULL`.

When it refuses, the ingestor stops on every start. The server also refuses to start,
because it checks the schema at startup. The log line names the column or the row count
and what to do. Nothing has been changed at that point, and v3.18.0 still starts on the
same database. After a successful rebuild v3.18.0 keeps working too, so a rollback is
safe either way.

If you ever added a column to `observers` by hand, check before upgrading.

### The content-hash migration from #787 now actually runs

Since #1283 this migration ran in the server on a read-only database handle, so it
changed nothing (#2409, closes #1856). It now runs in the ingestor in the background.

It only changes anything on installs that still hold transmissions from before #787 (April
18) and did not run a server between April 18 and May 18. For everyone else it is a
one-time scan that changes nothing. On a test with 1 million stale transmissions it took
4 minutes 38 seconds, and ingest never waited more than 199 ms on it.

When the pass changed rows, its summary log line asks you to restart the server. A
running server keeps the old hashes in memory until it restarts.

### With user accounts on, `users.db` moves to schema v10

The first start adds a revision counter to repeater details (#2429). A v3.18.x binary
refuses the database afterwards, so keep a copy of `users.db` from before the upgrade if
you may want to roll back. Without user accounts nothing changes.

### Signal per node now comes from direct receptions only

The SNR on an observation belongs to whichever node transmitted that copy last. Until
now, several pages averaged it over every packet a node was involved in, including
packets it only relayed or that were relayed to it. Those figures mostly measured the
last relay, not the node (#2451, #2452, #2453, #2454).

What you will see:

- **Avg SNR, Best Signal Quality, the home page "My Mesh" card and the node analytics
  grade** use only receptions of the node itself. A node no observer heard directly now
  shows no SNR instead of a misleading one. On a mesh with 1-byte hops that is more nodes
  than before.
- **"Heard By, direct"** no longer credits a node from a 1-byte last hop, a TRACE, an
  advert with an invalid signature, or a hop prefix a retired repeater shares.
- **The neighbour graph** no longer draws links from direct-route paths or TRACE
  packets, which name nodes still to come rather than the one the observer heard.
- **The node analytics page** has a new "Heard by observers" card: per observer, how
  often it heard the node and the median SNR.

For API users: `stats.avgSnr` on node health is `null` for nodes without direct
receptions. `topHops[].bestSnr`, `topHops[].medianSnr` (distance) and `hopsVsSnr`
(topology) are removed.

## Features

### Repeater planning

- **Coverage tab in the repeater planner** (#2406). Put a marker where you consider a
  new repeater, set its antenna height, and see who would hear it: the chance that a
  handheld hears the site, and line of sight to every known repeater in range. Needs
  `planner.enabled`. The handheld curve is fitted on drive tests in Belgium and can be
  tuned with `planner.userReach`.

### Maps

- **More map providers** (#2434, closes #2428). Topographic, satellite, gray and vector
  maps from EOX, OSM France, OpenFreeMap and VersaTiles, plus a hillshade overlay. Each
  group stays off until you set `map.tiles.providers.<group>.enabled: true`, so an
  upgrade changes nothing in the picker. Check each group's terms first: EOX 2025 imagery
  is non-commercial.
- **Your own tile servers** (#2434). `map.tiles.custom` adds raster, vector and overlay
  entries to the picker.
- **The picked map is remembered** (#2434). A map picked on Map, Live or the planner
  stays picked after a reload and on other pages, until the visitor picks Auto.
- **Map deep links** (#2442). A link with `observer=` now opens that observer's
  shortest path. The path picker writes the shown view to the URL, so a reload shows the
  same paths.
- **Link previews** (#2442). Set `CORESCOPE_URL` to your public address and shared links
  get an `og:url`. Preview images now come from your own instance instead of GitHub.

### Accounts and repeaters

- **Plain SMTP for account mail** (#2466, closes #2463).
  `userManagement.mail.provider: "smtp"` sends through any SMTP server, with STARTTLS
  or TLS and certificate checks. A login check runs at startup and sends nothing. SMTP
  has no delivery status, so a bounce only arrives in the sender's mailbox.
- **Send test mail** (#2466). A button in Admin, Overview mails your own address
  through the configured provider (Brevo, Postal or SMTP) and shows the error if it
  fails.
- **My repeaters** (#2430). My account lists the repeaters you claimed.
- **Repeater claims and edits from mobile apps** (#2429). An app can ask for a login
  that may claim repeaters and edit their details, next to the existing CoreDrive RX
  login. An app that sends the revision it edited no longer overwrites someone else's
  save: the second save gets the current details back. The browser editor does not send
  one yet.

### Nodes

- **One-byte repeaters link to the Prefix Tool** (#2412).

## Fixes

- **Rows lost at startup** (#2408). A packet committed while the server was loading at
  startup, or while a database read failed, could be missing from the server until the
  next restart. Both cases now reach the store.
- **Ingest stops after a broker restart** (#2413). When the MQTT broker rejected the
  subscription right after a reconnect, the ingestor logged "subscribed" and then
  ingested nothing until it was restarted. It now notices the rejection and retries.
- **Activity timeline** (#2435). The node analytics timeline now shows every hour of
  the window. Before, silent hours took no room, so an 11-hour outage looked like two
  neighbouring bars.
- **Repeater info** (#2437, #2440, #2450). An open edit form stays on screen when the
  page refreshes. Unclaim and Unlink stay disabled until the list has reloaded. A
  restored draft keeps the notice that someone saved in the meantime.
- **Node pages** (#2400, #2403). Packet, observation and relay counts use thousands
  separators (`12,278×`), and the Active and Uncertain explanations show their times
  with the same format and tooltips as the rest of the page.
- **Native Alpine builds** (#2410). Building from source on Alpine with gcc could crash
  on wide queries. Released images were not affected; the build now checks the thread
  stack size of every binary.

## Tests, CI and docs

The server race detector runs in four shards beside the Go tests (#2432), and the
accessibility gate runs its viewport and theme pairs at the same time (#2433). Planner
viewshed tests were trimmed and benchmarked (#2426, closes #2424; #2431), and a few tests
were made stable (#2404, #2423, #2438). The API reference now describes configured areas
(#2401) and the known channels catalogue (#2411).
